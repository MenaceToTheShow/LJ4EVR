# art/fonts: the hand-drawn 1-bit fonts

One text file per face, CC0, drawn by hand to the metrics in
`tests/fonts/advances_<face>.tsv`. `tools/fontpack.py` packs every `<face>.txt`
here into `src/gfx/lj_fonts_gen.c` in the `lj_font` layout of `src/gfx/lj_font.h`
and refuses a sheet whose cell or advances differ from the harvest.

## File

```
font sans13 height 13 ascent 11 descent 2 overhang 0
# any line starting with '#' is a comment; blank lines separate glyphs

glyph 32 3 space
...
...
(13 rows in all)

glyph 33 3 exclam
.#.
.#.
...
```

- Line 1: `font <name> height <h> ascent <a> descent <d> overhang <o>`; `<name>` is
  the file stem and the C symbol suffix (`lj_font_<name>`); the four numbers must
  equal the harvest.
- Then 224 glyph blocks, codes 32..255 in order (CP1252 bytes), each:
  - header `glyph <code> <advance> <name>` (`<advance>` must equal the harvest; `<name>`
    is a human label, `space`, `A`, `eacute`, ...; the packer ignores it),
  - exactly `<height>` rows of `#` (ink) and `.` (clear), each row exactly `<advance>`
    characters wide. The advance IS the cell: ink may be narrower, never wider. An
    advance of 0 (none harvested so far) would be `<height>` empty rows.
- Blank lines between blocks are optional; the row count is what delimits a glyph.
- Row 0 is the top of the cell; the baseline sits under row `ascent - 1`; rows
  `ascent .. height-1` are the descender area. An accelerator underline is drawn by
  `lj_text()` at row `ascent + 1`, not by the glyph.
- Encoding: ASCII only. Bytes 0x81 0x8D 0x8F 0x90 0x9D are undefined in CP1252; the
  harvest still carries their (default-char) advance, draw them as a box.
- A missing glyph is not allowed: every block is present, an undrawn one is all `.`
  (a skeleton). `lj_text()` draws an undrawn glyph as blank; the skeletons were
  generated by `fontpack.py --skeleton`, so drawing is filling ink into existing rows.

## Bold raster faces (sans13b, sans16b, ...)

Delphi's labels in a bold `MS Sans Serif` or `Courier` are GDI-synthesized bold: every
advance is the regular advance + 1 and the measured string is 1 px (`overhang`) wider
still. The sheet carries the +1 advances; `overhang` is a per-string constant that
`lj_text_width()` adds and `lj_text()` ignores. Draw a bold glyph as the regular glyph
overstruck 1 px to the right (that is what the ink looked like) if you want the classic
look; any ink inside the cell is legal.

## Workflow

1. `python -I tools/fontpack.py --skeleton <name>` writes `<name>.txt` from
   `tests/fonts/advances_<name>.tsv` if it does not exist.
2. Draw. Keep every row `<advance>` wide; a width slip is an error at pack time.
3. `python -I tools/fontpack.py` regenerates `src/gfx/lj_fonts_gen.c`;
   `python -I tools/fontpack.py --check` (CI) fails if the generated file is stale.
4. `lj4evr_tests font_corpus` proves every AutoSize label width from the 208 forms.
