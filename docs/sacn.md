# sACN sender (io/lj_sacn.c, io/lj_net.c)

W1 sacn track, 2026-10-21. The C port of `tools/ref/08-sacn_ref.py` `Sender`
(ANSI E1.31-2018), design 8.1 and 3.1, verdict rows ME-6, ME-23, ME-24. Contract:
`src/io/lj_sacn.h`, `src/io/lj_net.h` (docs/w1-contracts.md).

## What it does

- One UDP socket, `IP_MULTICAST_IF` set to the chosen NIC's `in_addr` (0.0.0.0 = the
  OS default interface), `IP_MULTICAST_TTL` (default 1), no `bind`. Destinations are
  `239.255.<hi>.<lo>:5568` per universe, or the link's unicast list (up to 8 addresses,
  the packet goes to each).
- Per-link state `{slots[512], seq, repeats_left, last_sent_us}`; link `i` feeds
  `cfg.universe_of_link[i]`, 0 = unmapped.
- `lj_sacn_set(universe, slots)` copies and, when any byte differs, sets
  `repeats_left = 3`. It never sends.
- `lj_sacn_pump(now_us)` sends at most one packet per universe per call: a pending
  repeat, else a keep-alive once 900 ms have passed since the last send. A universe
  sent less than 22727 us ago is skipped unless `cfg.unlock_rate` (ME-24; the next
  pump sends the latest frame, so coalescing loses nothing). Then universe discovery
  every 10 s to 239.255.250.214 with the mapped universes sorted ascending, and the
  packets-per-second window for the status line.
- A newly opened (or newly mapped) universe starts with `repeats_left = 3`, so the
  source announces itself on the first three pumps even when the frame is all zeros.
- `lj_sacn_open(cfg)` while already open is the reconfiguration path (ME-23): three
  Stream_Terminated packets for every universe the new map drops, the old socket
  closed, a new socket opened, and the state of every universe that stays mapped
  (slots, sequence) carried over, so a remap of link 2 from 2 to 7 terminates 2,
  announces 7 and leaves 1 untouched.
- `lj_sacn_close()` sends three Stream_Terminated per mapped universe and closes the
  socket; a second call is a no-op.
- `sendto` failures are counted (`lj_sacn_stats.send_errors`, `last_err`) and logged
  once per distinct error code, never fatal (08 s6.2: WinError 10051 when the NIC is
  down; discovery to multicast with `IP_MULTICAST_IF = 127.0.0.1` on Windows).
- Source name: CP1252 in `cfg.name`, converted with `lj_cp1252_to_utf8` when the
  packet is built, cut at 63 bytes like the oracle, NUL at octet 107.

## Threads (ME-23)

Sender state is file-static in `lj_sacn.c` (the header hands out no handle) and only
the engine thread touches it. `src/platform/sdl/lj_sdl.c` `lj_sdl_engine_main`:

```
lj_lock(); lj_engine_tick(); newcfg = lj_engine_take_sacn_cfg(); offline = lj_engine_is_offline(); lj_unlock();
if (newcfg) { copy it; lj_sacn_open(&copy); }                 /* LJ_CMD_SACN_CFG: close-old then open-new */
if (!offline) for each link: lj_sacn_set(universe_of_link[link], frame->out[link]);
lj_sacn_pump(now);
lj_lock(); lj_engine_set_sacn_stats(pps, last_err); lj_unlock();
...
lj_sacn_close();                                              /* after the loop, still on the engine thread */
```

The thread keeps its own copy of the `lj_sacn_cfg` the UI posted, so the UI may free
or reuse its struct after `lj_engine_view` shows the command was drained. The first
`LJ_CMD_SACN_CFG` is what opens the sender: the app posts it (with the config from
`lj_sacn_cfg_load`) before or right after `lj_platform_engine_start`. Shutdown order:
`lj_platform_engine_stop()` (joins; the thread has already closed the sender), then
`lj_sacn_close()` in `lj_app.c` as the documented no-op belt-and-braces, then
`lj_engine_destroy()`.

## Config (Hardware.Ini [SACN], installation-wide)

| Key | Value |
|---|---|
| `Nic` | dotted IPv4 of the NIC, `0.0.0.0` = default |
| `Name` | source name, CP1252, 63 bytes max; default `LJ4EVR <host>` |
| `CID` | 32 hex digits, UUID v4 generated by `lj_sacn_cid_new` (`rand_s` on Windows, `/dev/urandom` elsewhere, clock-mixed fallback) when absent; `lj_sacn_cfg_load` returns -1 so the app saves it once |
| `Priority` | 0-200 (clamped), default 100 |
| `TTL` | 1-255, default 1 |
| `Preview`, `UnlockRate` | 0/1 |
| `U1`..`U4` | universe per link, 0 = unmapped, default 1-4 |
| `Unicast1`..`Unicast4` | comma-separated dotted IPv4, up to 8; empty = multicast |

`lj_sacn_cfg_validate` (LORD_ENGINE-15) clamps priority to 200, ttl to >= 1, keeps the
NUL at `name[63]`, `nunicast` to 0..8, and for a universe outside 1..63999 (64214 and
65280+ included) or a duplicate of an earlier link returns the reason and leaves that
link unmapped (universe 0). `lj_sacn_open` logs the reason and carries on with the
rest; `lj_sacn_cfg_load` does the same at the trust boundary. `TickHz` is clamped to
10..200 by the model at load (ME-24 TickHz row, `LJ_TICK_HZ_MIN/MAX` in
`engine/lj_engine_rules.h`), which keeps the 900 ms keep-alive inside the 800-1000 ms
window; nothing here depends on the tick.

## Status line (Hardware Setup)

`lj_sacn_stats`: `packets[link]` since open, `pps[link]` = packets in the last whole
second, `universe[link]`, `send_errors`, `last_err`, `terminated`, `discovery`,
`nic_ipv4`. The engine thread copies `pps` and `last_err` into `lj_engine_status`
every tick (`lj_engine_set_sacn_stats`); the UI reads that copy.

Local proof 2026-10-21 (this PC, a 25-line driver at 5 s fade + 3 s idle, unicast
127.0.0.1, the Python receiver parsing with `08-sacn_ref.py`): tick 40 Hz -> 40 pps
steady; tick 80 Hz locked -> 40 pps; tick 80 Hz unlocked -> 80 pps; idle 1 pps; three
Stream_Terminated on close; no out-of-sequence, no send errors.

## Skipped on purpose

Sync packets, 0xDD per-address priority, IPv6 (documented non-compliance); discovery paging (4 links never exceed
one page). Art-Net is no longer skipped: it ships beside sACN since 1.1.0 (`docs/artnet.md`). sACN input (DMX-in) has
its own receiver rules and merge declaration in `docs/dmx-in.md` ("Receiver rules", "Merge"). The
`Sender.set()`-emits shape of the Python reference is not ported (ME-6).
