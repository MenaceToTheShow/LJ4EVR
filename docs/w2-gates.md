# W2 gates

Written 2026-10-21 by the W2 gatekeeper. Sources: `W1_CODE_MASTER_ELDER_VERDICT.md` section 5 (W2 entry gates) and
section 6 (LOW carry-forwards) plus the items `docs/w1-integration.md` sections 7, 9 and 10 ("Fix pass r1") left for W2;
`DESIGN_COUNCIL_MASTER_ELDER_VERDICT.md` section 5 (ME-30, ME-31, and the W0/W1 gates ME-15..ME-29 that every wave keeps
honouring) and section 6 (LOW rows tagged W2); design section 10 W2; `docs/fidelity.md` rows tagged W2;
`docs/w1-contracts.md` "Decisions recorded here". Both verdicts live in the vault under
`projects/_staging/lj4evr/delegations/`. `docs/w2-contracts.md` was not in the tree when this file was written; when it
lands, its track split decides the windows-a/b/c/d letters this file leaves to the integrator.

Owner is the W2 track that lands the row: model | engine | replay | midi | profiles | windows-a/b/c/d | desktop | app |
integrator. Where the brief does not say which windows sub-track owns a form, the row names the form and the integrator
assigns the letter. Shared files (`CMakeLists.txt` tests section, `tests/lj_tests.c`, `tools/glyphmap.tsv`,
`src/io/lj_actions.h`, `src/app/lj_app.c` bindings, `tools/test_layering.py` allowlists) are append-only for every
track. The W2 code-pass council ticks each row before `v0.2.0` is tagged; a row with no evidence is not ticked. The Status column is the Master Elder verdict's section 7 (`W2_CODE_MASTER_ELDER_VERDICT.md`, round 1) after the fix pass r1 items.
Severity: ENTRY = must be ticked before the tag; HONOUR = an earlier gate W2 code must keep meeting; LOW = carry-forward
the council may promote.
